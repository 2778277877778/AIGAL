## 1. 项目定位

### 1.1 它是什么
把《高中校园物语》的**固定剧本**换成**每局现场生成**的叙事层。玩家保留原版的校园日程玩法：每月 3 点行动点，去教室、图书馆、琴房、礼堂，推数值、触发事件、应对考试，最后走到两个结局之一。区别只在于——这一拍发生什么、谁说了什么、选项怎么措辞，每局都不一样。

### 1.2 它不是什么
- 不是纯聊天机器人。没有无限输入框，玩家仍在**有限选项**里做决定，这是 GAL 的交互骨架。
- 不是把剧本整个交给模型自由发挥。一旦模型能写数值和结局，多结局就不可控。
- 不是本期解决美术的项目。立绘、背景沿用纯色占位，后期补。

### 1.3 目标
| 目标 | 度量 |
|---|---|
| 每局体验不重复 | 同一 beat 的事件池 ≥3 候选，8 回合累计不重复率 ≥90% |
| 结局可控 | 相同存档重放，结局判定 100% 一致 |
| 断网可玩 | 无 key / 无网络时全流程可通关 |
| 单拍等待 | 生成中界面 ≤8 秒（超 12 秒降级） |
| 成本 | 每局 API 成本 ≤0.3 元（按 3 元/百万 token 估） |

## 2. 设计原则（5 条，冲突时按序号优先）

1. **判定链不进 AI。** 数值、Flag、考试、结局只走 `stats.rpy`。AI 的输出里没有数值字段。
2. **骨架固定，内容随机。** 第几回合、第几拍、几个选项由代码定；拍内事件、台词、选项措辞随机。
3. **无 key 也能玩。** 降级不是补丁，是一等公民：本地模板库必须覆盖全流程。
4. **AI 文本是外部输入。** 一律清洗后再进 `say`，不清洗等于让网页内容直接控制游戏。
5. **美术后置。** 任何逻辑不得依赖立绘/背景，占位图必须能跑通全流程。

## 3. 玩法规格

### 3.1 回合结构（8 回合）
```
月初：生活费 +150，AP = 3（T8 为 2；压力≥95 时再 −1）
  ├─ 事件拍 1（固定剧情拍，含选择）
  ├─ 事件拍 2
  ├─ 事件拍 3（随机事件槽：从事件池抽）
  ├─ 自由行动段：AP 2 点，玩家点地图/行动
  └─ 月末结算：exam_roll() → 考试线判定 → 数值结算 → 下月
```

### 3.2 数值（沿用，不改）
| 数值 | 初值 | 上限 | 关键阈值 |
|---|---|---|---|
| 学习 | 30 | 100 | 考试线 35/50/60/70 |
| 压力 | 10 | 100 | ≥80 失眠（正收益减半）；≥95 生病（AP −1） |
| 体力 | 40 | 100 | <20 正收益减半 |
| 金钱 | 100 | — | 月初 +150，行动消耗 |

### 3.3 行动与地图
沿用 12 个行动、10 个节点、解锁回合规则。行动效果查表，AI 不参与。

### 3.4 事件随机化
- **事件池**：每个 beat 声明 3–5 个候选事件，每个事件带 `weight`、`requires`（数值/Flag/回合条件）、`exclude`（互斥事件）、`tags`。
- **抽取**：先按条件过滤，再按权重抽，再对 `exclude` 去重；同局内已出的候选权重 ×0.3，避免重复。
- **随机化边界**：随机的是「这一拍发生什么 + 怎么演」，不随机的是「这一拍存在」和「它的数值后果」。数值后果由事件表固定，不交给 AI，也不让玩家从台词里猜。
- **确定性**：抽取用的 seed 在月初一次性掷好并存档，保证回滚/读档/重放可复现。

### 3.5 多结局
| 结局 | 条件（代码判定） | 正文 |
|---|---|---|
| TRUE「最后一个音」 | 学习 ≥75、压力 ≤70、6 个 TRUE_FLAGS 全触发 | AI 按结局规格生成（一次，缓存） |
| END「琴盖没开」 | 其余情况 | 按 `end_variant()` 取 A/B/C 三种变体，AI 各自生成一次 |

结局正文**每局只生成一次**并写入存档；结局判定永不读 AI 输出。

## 4. AI 叙事系统

### 4.1 四层职责
| 文件 | 职责 | 禁止 |
|---|---|---|
| `ai/schema.rpy` | 校验输出结构、清洗文本、校验 speaker/action_key/flag 白名单 | 不发起请求、不写 store |
| `ai/director.rpy` | 拼 prompt、选事件、调 provider、失败重试与降级 | 不直接联网、不判定结局 |
| `ai/provider.rpy` | HTTP 请求、线程、超时、熔断 | 不碰 store，不调 renpy.notify |
| `ai/cache.rpy` | 双层缓存、预取、LRU 封顶 | 不改 store 里的 dict 本体 |

### 4.2 输出契约
```json
{
  "lines":   [{"speaker": "zm", "text": "…"}],
  "choices": [{"text": "…", "action_key": "study"}],
  "flags":   ["heard_piano"],
  "mood":    "quiet"
}
```
硬约束：
- 没有数值字段。`action_key` 必须 ∈ `ACTIONS`，`choices` 为空时走默认选项。
- `flags` 只认该 beat 的 `allowed_flags` 白名单，且要求 `beat.turn == store.turn`；`TRUE_FLAGS` 与 `confession` 对 AI 拉黑；只 `set` 不 `unset`。
- `speaker` ∈ `mc/zm/zzb/zeng/stu_a/stu_b/inner`，其余一律丢弃。
- 单拍 `lines` ≤8 条，单条 ≤120 字，整段 ≤600 字。

### 4.3 文本清洗顺序（定死）
1. `renpy.filter_text_tags(t, allow=())`
2. `[` → `[[`
3. `{name}` → 玩家自定义名（名字本身先 sanitize，禁 `[` `{`）
4. 截断到上限

### 4.4 prompt 结构
```
[系统] 角色设定与分级约束（13+，不写血腥/恋爱露骨/政治）
[人物卡] 只取本拍相关角色各 150–200 字（从人物卡 v1 的 state_by_turn 取）
[状态] 回合 / 数值 / 可用节点 / 已触发 Flag / 最近 3 拍摘要
[事件] 本拍事件 id、必须包含的桥段、allowed_flags
[格式] 只输出 JSON，schema 附上
```
每拍输入 ≤3000 token，输出 ≤800 token。

### 4.5 缓存与预取
- key = `(schema_ver, prompt_ver, turn, beat_id, seed, choice_path)`
- 优先级：`store.ai_log`（进存档）> `persistent.ai_seen`（跨档，200KB 封顶）
- 预取：进入当前拍时后台生成**下一拍**（骨架已定，不会猜错）
- 跳过：`config.skipping` 为真时只读缓存/模板，不发现场请求
- 熔断：12 秒硬超时；连续 3 次失败 → 本会话离线模式

### 4.6 降级三档
| 档位 | 条件 | 行为 |
|---|---|---|
| AI | 有 key 且请求成功 | 正常生成 |
| 单拍降级 | 超时/失败/校验不过 | 用本地模板，顶部一行提示，不打断 |
| 离线 | 无 key / 连续 3 次失败 | 全部走模板，全流程可通关 |

## 5. 角色与文本

- **通用人物形象**：本期不做立绘绑定，`Character` 不带 `image=`。AI 与 UI 都不依赖脸。
- **人物卡**：`高中校园物语/人物卡_v1.md` + `.json`，从剧本反推，带出处与三级状态。每拍只喂相关片段，整卡塞 prompt 会挤掉场景信息。
- **主角自定义名**：开局输入，长度 1–8 字，禁 `[` `{` `}` 和换行；存档里存名字，prompt 里用 `{name}` 占位，AI 不得直呼本名以外的称呼。
- **未 define 角色**：夏幸悠、孔子帆、周父、周母在大纲里有戏，`characters.rpy` 尚无定义，落 T2–T8 前必须补 `xia / kong / zm_dad / zm_mom`。

## 6. API 与设置

- 协议：OpenAI 兼容 `POST {base_url}/chat/completions`。
- 可配：`base_url`、`model`、`api_key`、`temperature`、`timeout`。
- key 存储三档：`persistent`（默认，明文落盘，界面提示）/ 仅本次会话（内存，不落盘）/ 环境变量 `AIGAL_API_KEY`。
- 设置页含「测试连接」按钮，返回模型名与耗时。
- 日志脱敏：key 一律打码，请求体仅保留长度与前 200 字。

---

## 7. UI（沿用原版，只加三处）

1. **生成中界面**：纯色底 + 「生成中…」+ Esc 跳过（跳过即降级）。
2. **设置页扩一段**：API 区（base_url/model/key/测试连接）+ 生成强度（保守/标准/丰富）。
3. **调试页**（`config.developer` 才显示）：最近 5 次请求的原始响应、缓存命中率、当前 beat。

原版标题、对白、选项、地图界面不动。

---

## 8. 内容安全（13+）

- prompt 层：明确禁止血腥、性暗示、自残细节、真实政治人物；冲突用回避与化解处理。
- 输出层：固定词表过滤，命中即整拍降级重生成一次，再命中走模板。
- 长度与格式：超长直接截断，保证 UI 不破。
- 存档层：原始响应只在打开调试时落盘，默认不存。

## 11. 验收标准

- `dev.ps1 lint` 0 error；冒烟测试通过。
- 故障矩阵 10 项全过：2s 延迟 / 非法 JSON / 超时 / 500 / choices 空 / 超长文本 / `{image=...}` 注入 / `[persistent.api_key]` 注入 / 生成中 Ctrl / 生成中存档。
- 无 key 冷启动可完整通关，文本不空、选项不空。
- 相同存档重放，数值轨迹与结局一致。
- 注入文本不出现在界面上，也不出现在日志里。

## 12. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型输出破坏流程 | 卡死/乱码 | schema 校验 + 清洗 + 降级 |
| 延迟过高 | 体验差 | 预取 + 12s 超时 + 生成中界面 |
| 成本超预算 | 玩家流失 | 每拍 token 上限、缓存命中、默认短模型 |
| prompt 改动导致缓存失真 | 口吻不一致 | `prompt_ver` 进缓存 key |
| 玩家 key 泄露 | 安全 | 明文提示 + 会话模式 + 日志脱敏 |
| 无美术支撑 | 观感差 | 占位一致化、后期一次性补图 |

## 13. 待创立者决定

1. 苏瑶旧稿的外观设定：回收进人物卡，还是等美术？（现挂起，不进 prompt）
2. 模型与接口范围：首版只接一家 OpenAI 兼容端点，还是内置多家预设？
